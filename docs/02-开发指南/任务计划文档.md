## 2. 目标与范围
### 2.1 交付目标（最小闭环）
1. 玩家可移动（含基础状态切换）
2. 相机稳定跟随并保持 2.5D 视角
3. 至少一类敌人具备巡逻/追击与受击反馈
4. 攻击命中判定可生效（扣血/死亡）
5. HUD 展示基础信息（血量、提示）

### 2.2 当前阶段不做（非目标）
- 完整剧情系统
- 大规模关卡编辑器工具链
- Web 平台 C# 导出
- 复杂联网与多人同步

## 3. 执行节奏与协作规则
- 迭代周期：1 周 / 里程碑小循环
- 每日同步：昨日完成、今日计划、阻塞项
- 提交流程：最小可交付项开发 -> 最小自测 -> 代码和文档同批提交 -> 评审合并
- 完成口径：以里程碑验收项和评审清单为准

## 6. 质量门禁（DoD）
- 功能满足对应工作包验收标准
- 无无关改动和隐性耦合
- 关键流程有中文注释
- 文档同步更新（含日期）
- 提交前完成最小自测并记录

## 8. 风险与应对
| 风险 | 影响 | 应对策略 |
|---|---|---|
| 文档与代码脱节 | 开发方向偏移 | 每次功能提交同步更新文档状态与日期 |
| 过早引入复杂系统 | 进度失控 | 严格按 M0->M3 最小闭环推进 |
| 验收口径不一致 | 返工增加 | 以本计划的验收标准与清单为唯一口径 |
| 职责重叠导致冲突 | 协作效率下降 | 迭代开始前确认 RACI 与模块边界 |
