# 项目开发手册（C#版）

## 1. 文档信息
- 适用项目：`project_test`
- 技术栈：Godot 4.x .NET + C#
- 文档状态：当前有效
- 最后校验日期：2026-02-28
- 当前本地开发版本：`Godot Engine v4.6.1`

## 2. 项目目标
本项目目标是交付一个可运行的 2.5D ARPG Demo，满足以下最小闭环：
1. 玩家可移动（含基础动画状态切换）
2. 相机可稳定跟随玩家并保持 2.5D 视角
3. 至少一类敌人具备巡逻/追击与受击反馈
4. 玩家攻击可命中判定并产生结果（扣血/死亡）
5. HUD 展示基础信息（血量、状态提示）

## 7. 里程碑计划

### M0：工程可运行基线
目标：确认 Godot .NET 工具链可用。

任务：
1. 打开工程并生成 C# 解决方案
2. 创建基础目录结构
3. 配置输入映射（移动、攻击、冲刺、交互）

验收：
- 工程可编译
- 无脚本报错
- 输入映射存在且命名统一

### M1：角色 + 相机
目标：建立可操作的主循环。

任务：
1. 创建 `Player` 场景与控制脚本
2. 实现 8 向移动与基础状态切换
3. 实现相机跟随与基础平滑

验收：
- 玩家可移动，且速度/加速度参数可调
- 相机跟随无明显抖动

### M2：敌人与战斗闭环
目标：最小战斗链路可用。

任务：
1. 创建 `Enemy` 场景与追击逻辑
2. 实现攻击命中判定（Area/RayCast 二选一）
3. 实现生命值组件与死亡反馈

验收：
- 玩家可击中敌人
- 敌人可受击并销毁/失能

### M3：基础 UI 与可玩演示
目标：完成 Demo 体验层。

任务：
1. 加入 HUD（玩家血量、提示）
2. 加入受击/攻击反馈（动画、音效、闪白等）
3. 进行性能自检与参数收敛

验收：
- Demo 可完整运行 3 分钟无阻断错误
- 目标平台帧率满足预期（以实际硬件为准）

## 8. 开发规范

### 8.1 代码规范
- 命名语义化，避免缩写堆叠
- 关键流程必须有中文注释
- 避免一次性写大系统，按里程碑拆分提交

### 8.2 架构规范
- 保持“输入 -> 状态 -> 行为 -> 反馈”分层
- 公共能力优先组件化（如生命值、伤害、冷却）
- 场景职责单一，避免“上帝节点”

### 8.3 文档规范
- 文档只写“已验证事实”和“可执行步骤”
- 引用外部结论必须附链接
- 更新文档时同步标注日期

## 9. 测试与验证
- 单元测试：优先覆盖纯逻辑模块（状态机、数值计算）
- 集成验证：场景内运行验证移动、攻击、受击链路
- 回归检查：每次里程碑完成后更新验收勾选项

建议维护一份最小验收清单：
- [ ] 玩家移动
- [ ] 相机跟随
- [ ] 敌人追击
- [ ] 攻击命中
- [ ] 受击反馈
- [ ] HUD 正常

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 文档与代码脱节 | 开发方向偏移 | 每次功能提交同步更新文档日期与状态 |
| 过早追求复杂系统 | 开发周期失控 | 严格按 M0-M3 最小闭环推进 |
| 依赖社区二手结论 | 技术决策失真 | 关键决策只采信官方文档与官方仓库 |
| 平台能力误判 | 发布受阻 | 提前确认 C# 平台限制，避免 Web 目标 |
