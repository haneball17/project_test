## 💡 重要发现：Godot 的脚本能力

根据 [Godot 官方文档 - 脚本语言选择](https://github.com/godotengine/godot-docs/blob/master/getting_started/step_by_step/scripting_languages.rst)：

> **Godot 的设计理念**：几乎所有游戏功能都可以通过脚本实现，包括场景创建、节点操作、资源加载等。

**这意味着：**
- ✅ **场景节点可以通过脚本动态创建**
- ✅ **资源可以通过脚本加载和实例化**
- ✅ **项目配置可以通过代码读取和修改**
- ✅ **很多"手动操作"可以通过脚本自动化**

### 📝 动态场景创建示例

**我可以通过脚本完成以下工作：**

```csharp
// 示例：通过 C# 脚本动态创建完整场景
using Godot;

public partial class SceneBuilder : Node
{
    public static Node3D CreatePlayer()
    {
        var player = new CharacterBody3D
        {
            Name = "Player",
            Position = new Vector3(0, 0, 0)
        };

        // 添加精灵
        var sprite = new Sprite3D
        {
            Name = "Sprite3D",
            PixelSize = 0.01f
        };
        player.AddChild(sprite);

        // 添加碰撞体
        var collision = new CollisionShape3D
        {
            Name = "CollisionShape3D"
        };
        var shape = new BoxShape3D();
        shape.Size = new Vector3(1, 2, 1);
        collision.Shape = shape;
        player.AddChild(collision);

        // 附加脚本
        player.SetScript(GD.Load<Script>("res://scripts/PlayerController.cs"));

        return player;
    }
}
```

### ⚠️ 受限操作（需用户确认）

| 操作 | 限制原因 | 建议协作方式 |
|------|----------|--------------|
| **删除文件/代码** | 可能造成不可逆损失 | 先备份，再由用户确认后执行 |
| **Git 强制推送** | 可能覆盖他人工作 | 用户手动执行 |
| **外部资源下载** | 需遵守版权和许可 | 提供链接，用户手动下载 |
| **视觉调整** | 需要实时预览和视觉判断 | 用户在编辑器中调整 |

## 🔄 新的协作模式：脚本优先

### 📊 对比：手动 vs 脚本化

| 操作 | 传统手动操作 | 脚本化操作 | 节省时间 |
|------|--------------|------------|----------|
| **创建玩家场景** | 在编辑器中添加5个节点 | 运行一次脚本创建 | ~5分钟 |
| **设置多个属性** | 在 Inspector 中逐个设置 | 代码批量设置 | ~10分钟 |
| **添加输入映射** | 在 GUI 中逐个添加 | 脚本批量添加 | ~3分钟 |
| **配置项目设置** | 在多个面板中设置 | 修改 project.godot | ~5分钟 |

## 🚀 实战示例：脚本自动化场景

### 示例1：创建完整玩家场景

**【开发者A - 提供脚本】**

```csharp
// scripts/SceneFactory.cs
using Godot;

namespace ProjectTest.Scripts
{
    /// <summary>
    /// 场景工厂 - 通过代码动态创建完整场景结构
    /// </summary>
    public partial class SceneFactory : Node
    {
        /// <summary>
        /// 创建完整的玩家场景
        /// </summary>
        public static CharacterBody3D CreatePlayer()
        {
            // 根节点
            var player = new CharacterBody3D { Name = "Player" };

            // 碰撞体
            var collision = new CollisionShape3D { Name = "CollisionShape3D" };
            var shape = new CapsuleShape3D { Radius = 0.5f, Height = 1.5f };
            collision.Shape = shape;
            player.AddChild(collision);

            // 精灵
            var sprite = new Sprite3D { Name = "Sprite3D", PixelSize = 0.01f };
            player.AddChild(sprite);

            // 相机跟随点
            var cameraPivot = new Node3D { Name = "CameraPivot", Position = new Vector3(0, 12, 10) };
            player.AddChild(cameraPivot);

            var camera = new Camera3D { Name = "Camera3D" };
            camera.RotationDegrees = new Vector3(-55, 0, 0);
            cameraPivot.AddChild(camera);

            // 附加脚本
            var script = GD.Load<Script>("res://scripts/PlayerController.cs");
            player.SetScript(script);

            GD.Print("[SceneFactory] 玩家场景创建完成");

            return player;
        }
    }
}
```

**【开发者B - 使用方法】**

在 `Main.tscn` 的主脚本中调用：

```csharp
public override void _Ready()
{
    var player = SceneFactory.CreatePlayer();
    AddChild(player);
}
```

**无需在编辑器中手动创建任何节点！**

### 示例2：批量配置输入映射

**【开发者A - 提供脚本】**

```csharp
// scripts/InputConfig.cs
using Godot;

namespace ProjectTest.Scripts
{
    /// <summary>
    /// 输入管理器 - 自动配置所有输入映射
    /// </summary>
    public partial class InputManager : Node
    {
        public static void SetupInputs()
        {
            // 清除现有映射（可选）
            // InputMap.ActionRemoveEvents("move_up");

            // 配置移动输入
            ConfigureAction("move_up", Key.W, Key.Up);
            ConfigureAction("move_down", Key.S, Key.Down);
            ConfigureAction("move_left", Key.A, Key.Left);
            ConfigureAction("move_right", Key.D, Key.Right);

            // 配置动作输入
            ConfigureAction("attack", Key.Space, MouseButton.Left);
            ConfigureAction("dash", Key.Shift, MouseButton.Right);
            ConfigureAction("interact", Key.E);

            GD.Print("[InputManager] 输入映射配置完成");
        }

        private static void ConfigureAction(string actionName, Key key, MouseButton? mouseButton = null)
        {
            // 创建动作
            if (!InputMap.HasAction(actionName))
            {
                InputMap.AddAction(actionName);
            }

            // 添加键盘事件
            var keyEvent = new InputEventKey { Keycode = key };
            InputMap.ActionAddEvent(actionName, keyEvent);

            // 添加鼠标事件（如果有）
            if (mouseButton.HasValue)
            {
                var mouseEvent = new InputEventMouseButton
                {
                    ButtonIndex = mouseButton.Value
                };
                InputMap.ActionAddEvent(actionName, mouseEvent);
            }
        }
    }
}
```

**【开发者B - 使用方法】**

在项目的自动加载脚本或主场景中调用一次：

```csharp
public override void _Ready()
{
    InputManager.SetupInputs();
}
```

### 示例3：动态创建 UI

**【开发者A - 提供脚本】**

```csharp
// scripts/UIFactory.cs
using Godot;

namespace ProjectTest.Scripts
{
    /// <summary>
    /// UI 工厂 - 动态创建完整 UI 界面
    /// </summary>
    public partial class UIFactory : Node
    {
        /// <summary>
        /// 创建完整的 HUD 界面
        /// </summary>
        public static CanvasLayer CreateHUD()
        {
            var canvasLayer = new CanvasLayer { Name = "HUD" };

            var margin = new MarginContainer
            {
                Name = "MarginContainer",
                AnchorsPreset = Control.PresetFullRect
            };

            var vBox = new VBoxContainer
            {
                Name = "VBoxContainer",
                AlignmentMode = BoxContainer.AlignmentMode.Begin
            };

            // 顶部栏
            var topBar = new HBoxContainer { Name = "TopBar" };

            // 血条
            var healthBar = new TextureProgressBar
            {
                Name = "HealthBar",
                SizeFlagsHorizontal = SizeFlags.ExpandFill,
                MaxValue = 100,
                Value = 100
            };
            topBar.AddChild(healthBar);

            // 分数标签
            var scoreLabel = new Label
            {
                Name = "ScoreLabel",
                Text = "Score: 0"
            };
            topBar.AddChild(scoreLabel);

            vBox.AddChild(topBar);
            margin.AddChild(vBox);
            canvasLayer.AddChild(margin);

            GD.Print("[UIFactory] HUD 界面创建完成");

            return canvasLayer;
        }
    }
}
```

**【开发者B - 使用方法】**

```csharp
public override void _Ready()
{
    var hud = UIFactory.CreateHUD();
    AddChild(hud);
}
```

## 📌 更新的关键原则

### ✅ 新原则：脚本优先

1. **能用脚本就用脚本**
   - 场景创建、节点添加、属性设置都可以脚本化
   - 减少 GUI 操作，提高可重复性和可维护性

2. **一次性手动操作**
   - 仅项目初始化、资源首次导入需要手动
   - 后续都可以通过脚本自动化

3. **创意决策由用户决定**
   - 游戏玩法、美术风格、数值平衡由用户决策
   - 我（AI）负责技术实现

4. **视觉调整需要用户参与**
   - 相机角度、光照、特效等需要视觉判断
   - 但参数可以通过代码记录和复用

## 🆘 常见问题（更新版）

**Q: 为什么之前说需要手动创建场景？**
A: 这是我的误解。Godot 的脚本能力很强，大多数场景结构都可以通过代码动态创建。手动创建只是传统方式，不是唯一方式。

**Q: 脚本化创建有什么优势？**
A:
- ✅ **版本控制友好**：代码可以在 Git 中对比差异
- ✅ **可重复**：删除场景后可以一键重建
- ✅ **参数化**：可以通过参数调整场景结构
- ✅ **自动化**：可以集成到构建流程

**Q: 什么时候需要手动操作？**
A:
- 🎨 **视觉调整**：相机角度、光照效果需要实时预览
- 🎨 **动画制作**：关键帧动画需要美术直觉
- 🔧 **一次性配置**：项目创建、外部编辑器配置

**Q: 如何最大化协作效率？**
A: 采用**脚本优先**模式：
1. 我编写场景工厂脚本
2. 您运行脚本自动创建场景
3. 您仅做视觉层面的微调
4. 保存场景后可导出为 `.tscn` 文件供未来使用
